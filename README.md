# Анализ кредитных рисков  и оптимизация стратегии одобрения займов
  
  Проект посвящён анализу кредитного портфеля и поиску факторов, влияющих на вероятность
дефолта заёмщика.



# Инструменты
 
- SQLite / SQL — анализ данных
- Python / Jupyter Notebook — подготовка данных и преобразование CSV в базу SQLite
- Power BI — визуализация результатов
- DAX — расчёт показателей и метрик



# Структура проекта

credit_risk_dataset.csv   — исходный датасет
csv_to_db.ipynb           — преобразование CSV в SQLite           
credit_risk.sql           — SQL-запросы для анализа            
power_bi.txt              — рассчитанные столбцы и DAX-меры             
Credit_risk_pbi.pbix      — готовый Power BI отчёт      



# SQL-анализ
  
  Анализ состоит из 10 SQL-запросов. Запросы построены последовательно: результаты предыдущих
этапов помогают определить направление следующего анализа
  
  
  - 1. Общая статистика портфеля
    Здесь мы можем узнать сколько всего займов, сколько дефолтов, какой средний займ, какой суммарный объём портфеля.
  
  
  - 2. Дефолт по кредитному грейду
    Ключевой для понимания работает ли система оценки рисков.Я группирую данные по грейду и для каждой группы считаю количество займов, количество дефолтов, default rate, среднюю ставку и средний размер займа.
  
  
  - 3. Дефолт по целям займа
    Я группирую займы по шести категориям целей: личные нужды, образование, лечение, венчур, улучшение жилья и консолидация долга. Здесь мы можем увидеть что цель добавляет дополнительный контекст.

  
  - 4-5. Сегментайция по возрасту и доходу
    В этом запросе мы изучаем самого заемщика. Возраст позволяет увидеть что заемщик старше 40 лет как правило более устойчивкк финансово. Что насчет дохода, пятый запрос показывает какую часть дохода съедает платеж, т.е среднее отношение займа к доходу.

  
  - 6. Перекрестный анализ грейд на тип жилья
    Группирую данные по типу жилья и грейду мы ищем комбинайию факторов, которые дают больший риск. 

  
  - 7. Влияние прошлого дефолта
    Анализируя наличие предыдущего дефолта и текущего кредитного грейда, запрос показывает насколько ухудшается риск при наличии дефолта даже если у заемщика высокий грейд. Это помогает увидеть как улучшается точность предсказания. 

  
  - 8. Ранжирование
    Возможность увидеть что внутри одного грейда компания назначает заемщикам разные ставки.

  
  - 9-10. Профили риска
    Здесь я объеденил грейд, цель и тип жилья, что позволяет нам увидлеть портрет заемщика. Запрос считает по каждому грейду сколько суммарно выдано и сколько потеряно, какой процент составляют потери. Ключевое наблюдение здесь Grade G имеет самый высокий уровень дефолта — 98%, но Grade D может нести больший убыток так как займов выдано значительно больше. Это показывает разницу между процентным и денежным риском.

  

# Работа в Power Bi
  
  Я добавил 4 столбца: 
  - "Возрастная группа" - разбивает на пять групп и исключат заемщиков старще 80 лет 
  - "Сегмент по уровню дохода" - четыре уровня дохода для сортировки от низкого к высокому 
  - "Статус кредита" - преобразуем статус "0 и 1" в "Погасил" и "Дефолт" 
  - "Уровень риска" - где каждый заемщик получает классификацию от низкого до критического

  DAX-Меры
  - "Всего кредитов"
  - "Всего дефолтов"
  - "Сумма погашения" - означает количество погашенных займов
  - "Доля дефолтов"
  - "Общий объём портфеля" - суммирует все суммы займов
  - "Общие потери" - в денежном выражении
  - "Уровень потерь"
  - "Средняя процентная ставка"
  

# Результат

В результате анализа удалось:

- проверить связь кредитного грейда с фактическим уровнем дефолта
- определить влияние возраста, дохода, цели займа и типа жилья
- оценить влияние предыдущих дефолтов
- найти рискованные комбинации признаков
- сравнить относительный и абсолютный кредитный риск
- сформировать профили заёмщиков по уровню риска
- построить интерактивный Power BI отчёт для исследования кредитного портфеля

Главный вывод проекта — при принятии кредитных решений недостаточно ориентироваться только на уровень дефолта.
Сегмент с самым высоким процентом дефолтов не обязательно создаёт наибольшие финансовые потери. Стратегия одобрения должна учитывать вероятность дефолта, размер займа и объём выдач внутри сегмента
